# 「校遇」校园搭子匹配平台 · 功能说明文档

> 本文档按 **「每项功能 → 解决的对应需求 → 对应界面内容」** 三层结构，全面盘点平台现有全部功能，与实际实现严格一致，供后续查阅与迭代参考。

**技术栈**：Vue3 + Vite + Pinia + Vue Router + Element Plus（前端）；Express 5 + Socket.IO + `node:sqlite`（后端，零原生编译依赖）。
**运行方式**：`npm install` → `npm run seed` → `npm run dev`（前端 http://localhost:5173，后端 http://localhost:3000）。

**导航结构（登录后）**：
- 顶栏一级导航：推荐 / 大厅 / 日历 / 发布 / 我的搭子 / 快闪 / 兴趣圈 / 故事墙 / 校园活动 / 运营看板（仅管理员）+ 🤖 AI 助手 + 铃铛未读角标 + 头像下拉。
- 头像下拉菜单：我的画像 / 信誉与勋章 / 成长档案 / 我的申请 / 搭子周报 / 我的收藏 / 设置 / 退出登录。

## 一、账号与认证

### 1. 注册（校园邮箱）
- **解决的对应需求**：让用户以校园身份入驻平台，从源头保证用户为真实在校学生。
- **对应界面内容**：注册页（`/register`）含昵称、邮箱、密码三个输入框，页面固定提示「仅支持上财校园邮箱登录」；邮箱必须为七类上财校园邮箱后缀之一，密码需 8~20 位且同时包含字母与数字；命中白名单注册后自动完成邮箱认证，否则无法注册。

### 2. 登录
- **解决的对应需求**：快速、安全地进入平台。
- **对应界面内容**：登录页（`/login`）含邮箱 + 密码输入框与「登录」按钮，支持邮箱验证码找回密码。登录守卫：未登录访问受保护路由会跳转登录页，登录后回跳原页面。

### 3. JWT 认证与登录状态
- **解决的对应需求**：标识用户身份、保护接口与页面安全、维持会话。
- **对应界面内容**：无独立页面；由路由 `beforeEach` 守卫拦截未登录访问；token 与用户信息持久化在 `localStorage`（`dazi_token` / `dazi_user`），顶栏头像与昵称实时展示当前用户。

### 4. 校园邮箱认证
- **解决的对应需求**：通过可信域名证明「学生身份」，提升匹配可信度。
- **对应界面内容**：设置页「账号认证」卡片 →「校园邮箱认证」行；未认证时出现「立即认证」按钮，命中白名单域名自动通过，否则弹出 6 位验证码输入框；认证后显示「已认证」绿色标签。

### 5. 学生证认证（人工审核）
- **解决的对应需求**：为用户提供更强的实名学生身份标识。
- **对应界面内容**：设置页「账号认证」卡片 →「学生证认证」行，填写姓名、学号、专业并上传学生证正面照后提交；由管理员在运营看板中审核，通过后显示「已认证」，并在头像/主页/需求卡片等处展示「学生认证」标识。

### 6. 学号核验（人工审核）
- **解决的对应需求**：进一步强化身份真实性，提升推荐权重与信任度。
- **对应界面内容**：我的画像页底部「学生认证 🎓」卡片，未认证时填写「学号」「学校/学院」并「提交核验」；状态显示「未认证 / 审核中 / 已认证」。管理员在运营看板的「学号核验」表格中通过/驳回。

### 7. 隐私设置
- **解决的对应需求**：保护用户个人隐私，自主控制信息可见范围。
- **对应界面内容**：设置页「隐私设置」卡片，两个开关：「展示学校 / 学院」「展示年级」，关闭后他人页面不再显示对应信息。

### 8. 账号注销
- **解决的对应需求**：满足用户退出并删除全部数据的诉求。
- **对应界面内容**：设置页「账号注销」红色警示卡片 →「注销账号」按钮，二次确认后删除账号及数据并返回登录页。

## 二、个人画像与主页

### 9. 我的画像（编辑）
- **解决的对应需求**：完善个人画像以显著提升匹配精准度（五维引擎中兴趣标签与空闲时段权重最高）。
- **对应界面内容**：我的画像页（`/me`）表单：昵称、消费偏好（经济/适中/随性）、学校/学院、年级、个人简介（140 字）、兴趣标签（多选可自定义）、每周空闲时段（按天选时间段 + 可增删）；下方「课表热区」以 8:00–22:00 的表格热力图可视化展示所选空闲时段；「保存画像」提交。

### 10. 他人公开主页
- **解决的对应需求**：搭子间相互了解，辅助信任判断（配合信誉与履历）。
- **对应界面内容**：用户主页（`/user/:id`）展示：头像、昵称、信誉档位标识、学生认证/邮箱认证标签、学校/年级、消费偏好、简介；「搭子档案」统计（信誉分、组队次数、平均评分及数量、好评数）；「标签云」（来自互评标签的频次词云）；「兴趣标签」；「老搭子」列表（合作次数、对方信誉分）；「勋章」列表；右上「拉黑」按钮。

## 三、需求发布与浏览

### 11. 发布搭子需求
- **解决的对应需求**：结构化描述「想找什么样的搭子」，让撮合更精准。
- **对应界面内容**：发布页（`/publish`）表单：搭子类型（卡片式选择，6 类 + 其他）、标题（50 字）、补充说明、活动时间（起止日期时间）、活动地点、需要人数（1–10）、相关标签（多选可自定义）、「设为周期搭子」（勾选后出现「周期说明」输入框）。支持从故事墙「发起同类组局」跳转时预填分类/标题/标签。

### 12. 搭子类型（分类体系）
- **解决的对应需求**：覆盖校园高频搭子场景，并为差异化字段模板与破冰话题提供依据。
- **对应界面内容**：发布页分类卡片展示七类：学习搭子 📚、饭搭子 🍚、运动搭子 🏀、游戏搭子 🎮、比赛组队 🏆、出行搭子 🚗、其他 ✨。后端为前六类各自定义差异化字段模板（如学习：时间段/自习地点/目标/安静偏好；饭：餐段/预算档位/忌口标签 等）。

### 13. 需求大厅（筛选/搜索/排序）
- **解决的对应需求**：从海量需求中快速定位最符合条件的目标。
- **对应界面内容**：大厅页（`/hall`）筛选栏：分类单选（全部 + 六类）、关键词搜索、状态筛选（招募中/已匹配/已结束/已过期）、排序（最新发布/活动时间/缺口最多）、「只看已认证」复选、「筛选」按钮。需求卡片展示：分类 emoji、标题、状态标签、活动时间、地点、申请/需要人数、标签、周期搭子标识、发起人昵称与信誉分、学生认证标识。

### 14. 需求详情
- **解决的对应需求**：完整了解单条需求的全部信息以便决策。
- **对应界面内容**：详情页（`/demand/:id`）展示：标题、状态、周期搭子标识、分类、时间区间、地点、人数、标签、描述、周期说明；24 小时内临期时顶部出现「行前安全提醒」；下方依次为：五维匹配解释（雷达图 + 条形解释 + 总结句）、发起人卡片（信誉分 + 档位 + 认证标识）、举报/拉黑操作、相似需求推荐、申请/收藏/一键重发按钮。

### 15. 活动日历（周视图）
- **解决的对应需求**：从时间维度直观把握本周供需密度，方便规划。
- **对应界面内容**：日历页（`/calendar`）展示本周 7 天，每天列出当日需求（时间 + 分类 emoji + 标题 + 人数），未满员高亮、今天高亮；支持「上一周 / 下一周」切换；点击事件跳转需求详情。

### 16. 收藏与我的收藏
- **解决的对应需求**：标记感兴趣的需求以便后续跟进与一键申请。
- **对应界面内容**：需求详情「收藏 / 已收藏」切换按钮；「我的收藏」页（`/favorites`）列表展示收藏需求（分类、标题、时间、地点、人数、标签、发起人），支持「取消收藏」，点击进入详情。

### 17. 一键重发
- **解决的对应需求**：需求过期后无需重复填写即可再次发布。
- **对应界面内容**：需求详情页，当为本人发布的需求时显示「我发布的需求」标签与「一键重发」按钮，点击后生成新需求并跳转其详情。

## 四、匹配推荐（五维可解释引擎）

### 18. 个性化推荐
- **解决的对应需求**：解决「不知道找谁」的核心痛点，用可解释模型为每位用户推荐最合适的搭子。
- **对应界面内容**：推荐页（`/`）顶部问候区展示「为你推荐 N 个可能一拍即合的搭子」与分类快捷筛选 chips；需求卡片右侧显示「XX% 匹配」，卡片内展示「💡 总结句」与「为什么推荐」（最多 3 条理由）。点击「不感兴趣」将发起人加入负样本并从列表移除。

### 19. 五维匹配解释（雷达图）
- **解决的对应需求**：让匹配结果可解释、可信任，消除「黑箱」疑虑。
- **对应界面内容**：需求详情「你与这条需求的匹配度」卡片：右上匹配百分比、总结句、SVG 五维雷达图 + 条形解释列表（每维显示对应 score 进度条与提示文案）。
- **五维与权重**：兴趣 0.3、时间窗重合 0.25、信誉（发起人信誉 + 学生认证加成）0.13、老搭子 0.12、活跃度 0.08；得分按参与维度权重归一化计算。

## 五、申请与组队

### 20. 申请加入
- **解决的对应需求**：建立「发起人审核」的双向选择机制，保证组队质量。
- **对应界面内容**：需求详情页「立即申请」按钮（已申请变为禁用「已申请」）；申请提交后端做风险检查。

### 21. 申请中心（我发出的 / 收到的）
- **解决的对应需求**：集中管理所有申请，支持发起人通过/拒绝以推进组队。
- **对应界面内容**：申请中心页（`/applications`）两个 Tab：「我发出的」展示每条申请的需求、时间、需求状态、申请状态（待处理/已通过/已拒绝），已通过提供「查看队伍」；「收到的」展示申请人（昵称、认证标识、信誉分、留言），待处理时提供「通过 / 拒绝」按钮。

### 22. 组队（满员自动成队）
- **解决的对应需求**：申请通过后自动组建/加入队伍，形成可对话的群体。
- **对应界面内容**：发起人「通过」申请后，系统 `ensureTeam/addMember` 自动建队并加入成员，人数满员时自动激活队伍；通过方收到「已加入队伍，可前往『我的搭子』聊天」提示。

### 23. 我的搭子（进行中 / 已结束）
- **解决的对应需求**：清晰呈现当前与历史上的搭子关系。
- **对应界面内容**：我的搭子页（`/teams`）分「进行中」「已结束」两组卡片；每张卡片展示分类 emoji、需求标题（可点进详情）、活动时间、状态标签、成员头像列表（标注「队长」「我」）、右侧「打开聊天室」按钮；成员下方展示「关系卡片」：信誉档位 tier + 关系等级 rel_level（老搭子/熟悉/初识）+ 合作次数 + 共同兴趣标签。

### 24. 队伍生命周期管理
- **解决的对应需求**：让队长/成员可主导队伍的结束、解散与退出。
- **对应界面内容**：聊天室顶栏，队长可见「完成活动」「解散」按钮；非队长可见「退出」按钮；完成后触发搭后互评。

## 六、聊天与实时互动

### 25. 聊天室（实时消息）
- **解决的对应需求**：组队后即时沟通、商议活动细节，解决「没被拉群」的断层。
- **对应界面内容**：聊天室（`/chat/:teamId`）展示需求标题、状态、成员数与分类；消息区气泡（自动区分系统消息/自己/他人，显示发送者昵称）；底部输入框 + 发送（支持回车发送，`canChat` 对全体成员开放，不限制队伍状态）；敏感词自动脱敏。

### 26. 活动详情面板
- **解决的对应需求**：在聊天场景内随时查阅活动关键信息。
- **对应界面内容**：聊天室顶部「活动详情」卡片可收起/展开，展示分类、起止时间、地点、描述、成员列表（队长标识）、破冰话题横幅。

### 27. 破冰话题
- **解决的对应需求**：降低组队初期尴尬，快速开启对话。
- **对应界面内容**：聊天室活动详情内「💬 破冰话题」横幅（按需求分类从话题库随机推送）。

### 28. 破冰快问快答小游戏
- **解决的对应需求**：用游戏化方式促进成员相互了解。
- **对应界面内容**：聊天室「快问快答 🎲」按钮打开弹窗，随机展示 10 个破冰问题之一，支持「换一题」，可「发到聊天室」一键填入输入框。

### 29. AI 助手（全局）
- **解决的对应需求**：为全站用户提供统一的智能问答与操作指引（demo 版，为后续接入大模型预留），服务于全局而非单一聊天室。
- **对应界面内容**：全局顶栏（消息通知铃铛图标左侧）「🤖 AI」入口，任意页面均可点击打开对话弹窗；规则式助手可回答破冰话题/安全建议/组队技巧/信誉说明等关键词；调用占位接口 `POST /api/ai/chat`（不绑定具体队伍，全站通用）。

### 30. 安全中心与 SOS
- **解决的对应需求**：线下见面的人身安全保障。
- **对应界面内容**：聊天室「安全中心」按钮打开弹窗：行前安全提醒、紧急联系人展示（未设置引导到设置页）、「🆘 一键 SOS（模拟求助）」按钮，点击后提示已模拟向联系人发送求助与位置。

## 七、搭后互评与信誉体系

### 31. 搭后互评
- **解决的对应需求**：以「爽约=负向信誉」取代签到，通过双向评价约束履约、沉淀口碑。
- **对应界面内容**：队长「完成活动」后弹出「搭后互评 🌟」弹窗，对每位其他成员打分（评分 0–5）+ 选择正面标签（守时/靠谱/好相处/幽默/有活力/乐于分享）+ 可选负面标签「爽约」；「提交评价」后写入。

### 32. 信誉分与档位
- **解决的对应需求**：用可量化的信誉作为搭子互信的硬性依据。
- **对应界面内容**：信誉与勋章页（`/credit`）展示当前信誉分大数字、档位 + 状态、进度条、统计（组队/好评/差评/爽约）、信誉流水表格（行为、分值变化、时间），并列出加减规则说明。档位：金牌搭子 4.6+ 🥇、靠谱搭子 4.2+ 🤝、友好搭子 3.8+ 🙂、观察期 0+ 👀。
- **加减规则**：完成好评 +0.1、好评标签 +0.05/个、差评 −0.2、爽约 −0.5、举报成立 −1.0；初始 5.0，区间 1.0–5.0。

### 33. 勋章体系
- **解决的对应需求**：用成就徽章激励正向履约行为。
- **对应界面内容**：信誉与勋章页、用户主页、成长档案均展示勋章。5 类：首次组队、守约十次（累计 10 次守时好评）、金牌搭子（信誉 ≥4.6）、破圈达人（累计组队 20 次）、老搭子（与同一位搭子合作 ≥3 次）。

## 八、治理与安全

### 34. 举报
- **解决的对应需求**：让用户共同治理违规内容，维护平台秩序。
- **对应界面内容**：需求详情页「举报」按钮打开弹窗，选择原因（虚假信息/广告营销/人身攻击/涉及诈骗/其他）+ 补充说明，提交后进入管理员举报工作台。举报成立自动对当事方扣分（−1.0）。

### 35. 拉黑与黑名单
- **解决的对应需求**：屏蔽不想再看到的用户，隔离不良体验。
- **对应界面内容**：需求详情/用户主页提供「拉黑该用户」；设置页「黑名单」卡片列出已拉黑用户（头像、昵称、学校、拉黑时间），支持「解除」。

### 36. 不感兴趣（负样本反馈）
- **解决的对应需求**：通过负反馈持续优化推荐结果，减少无效推荐。
- **对应界面内容**：推荐页需求卡片右下「不感兴趣」按钮，点击后移除该需求并将发起人加入负样本。

### 37. 紧急联系人
- **解决的对应需求**：线下遇险时可一键求助。
- **对应界面内容**：设置页「安全设置」卡片，填写紧急联系人（如「妈妈 138****0000」）并保存；聊天室安全中心会展示该联系人并支持 SOS。

### 38. 敏感词过滤
- **解决的对应需求**：拦截诈骗、交易、色情赌博等风险内容。
- **对应界面内容**：无独立页面；在需求发布、聊天消息、圈子发帖、故事发布等入口自动拦截/脱敏。词表：诈骗、陪聊、刷单、加微信转账、转账、定金、私下交易、色情、赌博、高利贷、代考、代写、枪手等。

### 39. 行为风控
- **解决的对应需求**：对高频爽约/差评用户做风险限流。
- **对应界面内容**：无独立页面；后端在申请/推荐时基于爽约率（>30%）与差评率（>40%）做风控判断。

## 九、快闪组局

### 40. 快闪搭子
- **解决的对应需求**：满足「临时起意、即刻组局」的轻量短局需求（即兴约饭/约球/开黑）。
- **对应界面内容**：快闪页（`/flash`）顶部「发起快闪」按钮；列表展示进行中的快闪卡片（分类 emoji、标题、分类/发起人、开始时间/时长/地点、成员头像与人数、加入状态）；「立即加入」空位即报，满员自动 full；发起人可「关闭」。发布表单：标题、类型、地点、时长（15–480 分钟）、开始时间、需要人数（2–10）。

## 十、兴趣圈

### 41. 兴趣圈 / 部落
- **解决的对应需求**：基于兴趣建立长期社群，从「一次性组队」延伸为「持续连接」。
- **对应界面内容**：兴趣圈页（`/circles`）「创建圈子」按钮；圈子卡片（名称、分类、简介、成员数、已加入标识）；选中后展示圈子详情 + 帖子列表，「加入圈子」后方可发帖（发帖敏感词自动拦截），可「退出圈子」。创建表单：名称、分类、简介。

## 十一、故事墙（UGC）

### 42. 心得故事发布
- **解决的对应需求**：沉淀真实搭子经历，形成口碑与社区氛围，并为新人提供「同类组局」入口。
- **对应界面内容**：故事墙页（`/stories`）顶部「分享新故事」表单：标题、心情（多选，开心/收获/感动/成长/惊喜/怀念/其他，最多 5 个）、关联搭子类型（可选）、正文、配图（本地存储、单张 ≤500KB、最多 9 张），支持「保存草稿」或「保存并发布」。

### 43. 故事浏览与互动
- **解决的对应需求**：展示与传播组队故事，形成内容消费与轻社交。
- **对应界面内容**：故事墙两个 Tab「故事墙 / 我的故事」；卡片展示作者（头像/昵称/学校/时间/信誉档位）、草稿标识、心情标签、标题、正文、图片；footer 提供「点赞」（❤/🤍 + 计数）、草稿「发布」、公开故事「🚀 发起同类组局」（带分类/标题跳转发布页）、本人故事「删除」。

## 十二、校园活动

### 44. 发布资格申请
- **解决的对应需求**：保障大型活动/招募信息的真实可靠（需管理员审核）。
- **对应界面内容**：校园活动页（`/activities`）顶部说明横幅 + 按钮；普通用户「申请发布资格」弹窗填写活动名称、申请主体、活动分类、申请用途（必填）、拟举办时间、地点；管理员在运营看板「校园活动发布申请」表格中通过/驳回（可附驳回原因），通过后用户获得一次发布机会。

### 45. 发布校园活动
- **解决的对应需求**：规范发布大型活动/招募。
- **对应界面内容**：「使用发布机会（剩 N 次）」或管理员「直接发布活动」打开发布弹窗：标题、主办方、分类、详情、时间、地点、报名/联系方式、名额（留空不限）、标签；发布消耗一次机会。

### 46. 活动大厅与报名
- **解决的对应需求**：浏览校园活动并一键报名。
- **对应界面内容**：校园活动页「活动大厅」Tab，支持搜索活动/主办方、按分类筛选；活动卡片展示分类、标题、主办方、时间、地点、名额、简介。详情页展示完整信息 + 「立即报名」「取消报名」，活动结束后不可报名。

### 47. 参与证明闭环
- **解决的对应需求**：让参与校园活动可被记录、可被证明（第二课堂佐证）。
- **对应界面内容**：发布者点击「结束活动 · 发放参与证明」后，为所有已报名用户发放参与证明；用户「我的报名/参与证明」Tab 中已报名活动显示「🎓 参与证明已颁发」；详情页展示「已参与 · 已获参与证明」状态；发布者可见报名名单。

## 十三、成长档案与激励

### 48. 成长档案（第二课堂成绩单）
- **解决的对应需求**：把「校遇」行为累积为个人成长数据，增强平台长期价值。
- **对应界面内容**：成长档案页（`/growth`）：顶部会员等级卡片「当前等级权益 + 距离下一级还需组队次数」；成绩单指标（累计组队、完成活动、校园活动、发布故事、获得好评、信誉分及状态）；我的勋章；老搭子列表（关系等级 + 合作次数）；往期纪念（已完成活动的时间线）。

### 49. 会员等级
- **解决的对应需求**：以成长等级激励持续使用（展示型，不涉及真实付费）。
- **对应界面内容**：成长档案顶部会员卡片展示三档：青铜 🥉（基础匹配、发布 3 条需求）、白银 🥈（优先推荐、发布 6 条、快闪组局）、黄金 🥇（身份徽章、不限量发布、专属客服），按累计组队次数 0/5/15 划分。

### 50. 搭子周报
- **解决的对应需求**：周期性回顾，强化用户粘性与成就感知。
- **对应界面内容**：周报页（`/weekly`）「本周小结」卡片（新组队、消息数、当前信誉分、信誉状态）；「近期信誉动态」（近 7 天信誉流水 + 正负变化）；「值得续约的搭子」（可跳转对方主页）。

## 十四、通知与运营支撑

### 51. 通知系统
- **解决的对应需求**：及时触达申请/通过/组队/互评等关键事件。
- **对应界面内容**：顶栏铃铛显示未读角标，点击进入「消息通知」页（`/notifications`）；列表展示各类型通知（申请🙋/通过✅/未通过ℹ️/组队🎯/互评⭐/系统📢），未读高亮，支持「全部已读」；通过 Socket 实时推送未读。

### 52. 定时任务与召回
- **解决的对应需求**：自动化维护数据新鲜度并唤醒沉默用户。
- **对应界面内容**：无独立页面；后端调度器每 60 秒执行：需求自动过期（expireDemands）、临期活动提醒（remindUpcoming）、沉默用户召回（recallDormant）、行为风控扫描（riskScan）。

### 53. 管理员运营看板
- **解决的对应需求**：管理员掌握平台核心指标并处理治理事务。
- **对应界面内容**：运营看板页（`/admin`，仅管理员可见）：
  - 指标卡片：注册用户、认证用户、完善画像、需求总数、活跃需求、队伍数、已完成队伍、待处理举报、待审活动发布；
  - 转化漏斗（注册→完善画像→首次行动→发起申请→组队→完成活动）；
  - 搭子类型分布（柱状）；
  - 举报工作台（成立/驳回，成立即扣分）；
  - 校园活动发布申请审核（通过/驳回）；
  - 学号核验审核（通过/驳回）。
